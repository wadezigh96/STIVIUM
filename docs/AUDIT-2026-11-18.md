# STIVIUM Audit — 18 November 2026

Audited commit: `3f71e208122f8e4fff1c57c3a3fc4eebb091e73b` (HEAD, `main`)
Auditor: Muse (automated audit, read-only checks plus documented fixes below)
Scope: full repository — static marketplace UI, JS modules, Hardhat contract,
Python provider, CLI, docs, and Kiroween 2026 submission readiness
(FRANKENSTEIN category, submission period 30 October – 4 December 2026).

## Verdict

The core marketplace is real and works: browse, compare, score, and the
seeded 16-agent catalog are verified correct, the live demo loads on
GitHub Pages and Vercel, and no secrets are committed. But the repository
has drifted: between the 6 October 2026 audit (commit `c3ff94e`) and today
the app was deliberately moved into a testnet-only mode — local/mock
activation was removed, the swap was gated off, and Altana was disabled —
while the README and most docs still describe the old behaviour. A judge
following the written judge path today **cannot complete the activation
step** without a funded testnet wallet. That is the single most important
finding (F1). The doc corrections in this audit make the repository honest
about the current build; the activation gap itself needs an owner decision
(see "Still needs the owner").

## Findings

### F1 — CRITICAL: the judge path cannot be completed (no local activation)

`app.js` removed the local/mock activation path. Confirming a hire now
always calls `window.__stiviumPrivy.hireErc8183Testnet(...)`, which
requires a connected Privy wallet, BSC Testnet BNB for gas, 0.10 testnet
U for escrow, and a provider address — only YieldCartographer ships with
one prefilled (`0xFCeAfEc082f9e8B17CDB51f33C3D5c9759a25E03`, ERC-8004
#2577). Without all of that, activation fails with an error and the
revoke step is unreachable. Yet these docs still describe local
activation:

- `docs/KIROWEEN-SUBMISSION.md` judge path step 5: "Confirm local
  activation or, when available, follow the labeled BNB testnet path."
- `docs/evidence/JUDGE-PATH.md` steps 5–6 and "No wallet required for
  UI walkthrough."
- `docs/SUBMISSION.md`: "Activation defaults to a local policy-scoped
  mode for the public prototype."
- `.kiro/specs/stivium-marketplace/requirements.md` story 4 and
  `design.md` safety boundaries; `.kiro/steering/product.md` ("a judge
  can complete the main flow even when an external data source is
  unavailable").

The 6 October audit snapshot recorded "Mode: local mock" — the removal
happened during the testnet-only pivot (commits `6f94b07`, `d528f17`,
`1e92c26`). **Fix applied in this audit:** the judge-facing docs now
describe the real ERC-8183 testnet hire. **Still needs the owner:** decide
whether to restore a local/demo activation mode for judges (see "Still
needs the owner").

### F2 — HIGH: swap is disabled but documented as live

`swap-ui.js` `ensureBsc()` throws unconditionally ("Swap is temporarily
disabled..."), and it is called first by both the quote and the execute
handlers, so **neither quotes nor swaps work**. The README ("Live
PancakeSwap"), `docs/SWAP.md` ("live, non-custodial PancakeSwap V2 swap
path... can submit real BNB Chain transactions"), `docs/TERMIX.md`, and
the `index.html` footer ("live PancakeSwap execution") all claim the
opposite. A second, independent block exists: `privy-bridge.js`
`sendTransaction` rejects `chainId: 56` (testnet-only), while the swap
code passes `chainId: 56`. The gate was deliberate
(`6f94b07 safety: block mainnet swap while migrating to testnet`), so the
code was left alone and the docs were corrected instead.

### F3 — HIGH: Altana is disabled but documented as live

`altana-wire.js` `ensureClient()` throws unconditionally ("Altana
execution is disabled in STIVIUM Testnet-only mode..."), so the
"Connect Altana" button and every grant/execute/revoke call fail. The
README, `docs/ALTANA.md`, `docs/X402.md`, `docs/JUDGING.md`,
`docs/ROADMAP.md` (Phase 2), and `skills/README.md` still present Altana
session keys as available. `docs/ALTANA.md` also instructs judges to
"enable On-chain Altana session" — no such toggle exists in the current
modal — and contradicts the module itself: the docs say testnet
(chain 97) while the module is mainnet-oriented (chain 56, BSC mainnet
RPC, bscscan.com). The 6 October on-chain proof
(`docs/evidence/ALTANA-ONCHAIN-PROOF-2026-10-06.json`) is historical
evidence from before the disable, not proof the current build works.

### F4 — HIGH: x402 hire mock removed from the UI but documented as shipping

The activate modal has no x402 checkbox (the `#x402Pay` listener in
`app.js` has no matching element, and `state.x402` is always false), and
the mock receipt flow is gone; the x402 row now reads "x402 integration
unavailable · no payment sent". The README, `docs/X402.md` ("What ships
in the demo"), `docs/TERMIX.md`, and the Kiro spec still describe the
mock as part of the demo. The x402 story now exists only as
documentation.

### F5 — HIGH: agent card claimed READY but the URL 404s

`docs/SET-AND-EARN.md` marks "Public agent card |
/.well-known/agent-card.json" as READY and links
https://stivium.vercel.app/.well-known/agent-card.json, but that URL
returns HTTP 404 (verified 18 Nov 2026) and no `.well-known/` directory
exists in the repo. The card is served only by the Python provider
(`erc8183-provider/`, `GET /.well-known/agent-card.json`), which has no
recorded deployment (`ERC8183_AGENT_URL=https://YOUR_PROVIDER_HOST/...`
is still a placeholder). Status corrected to NOT VERIFIED in this audit.

### F6 — MEDIUM: `docs/ARCHITECTURE.md` is stale

It describes a "single-file, zero-dependency prototype" with functions
`scoreRarity()` / `scoreTrending()` / `renderGrid()` inside `index.html`.
The code was split into modules long ago (the real entry points are
`computeScores()` / `render()` / `renderModal()` in `app.js`), and the
app is not zero-dependency: wallet features load React, Privy, and viem
from the esm.sh CDN at runtime. "Activation → local activated map" is
also stale per F1. Rewritten in this audit.

### F7 — MEDIUM: `live-snapshot.json` was 8 weeks stale

`generated_at` was 2026-09-23 (prices: BNB $795). Refreshed in this audit
with the repo's own script (`python3 scripts/refresh-live.py`):
`generated_at` is now 2026-11-18T16:58:30Z with 4 live samples. Note the
registry count changed from 324,602 to 2,837 — that is the live
8004scan API's current answer, not a script error.

### F8 — MEDIUM: no automated tests for the contract or the UI

`test/` directory, so `AgentRegistry.sol` is untested. There are no tests
for the scoring or activation logic either (the only test suite is the
Python task engine, 5/5 passing). The scoring formulas were verified
manually in this audit (see "What verified clean").
