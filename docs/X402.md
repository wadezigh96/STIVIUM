# x402 hire payments (B402 on BNB)

Stivium treats **payment** and **permissions** as separate layers:

| Layer | What it controls | In this prototype |
|-------|------------------|-------------------|
| **x402 / B402** | Who pays how much for the hire / job | UI mock + docs (this file) |
| **Altana session keys** | What the agent may call, spend cap, expiry | `altana-wire.js` + on-chain toggle |

## What is x402?

HTTP-native micropayments. A resource responds with **402 Payment Required** and payment instructions. The buyer signs an off-chain authorization (EIP-712 / EIP-3009 or Permit2). A **facilitator** (on BNB: **B402**) verifies and settles on-chain, often sponsoring gas.

Stablecoins on BSC: U, USD1, USDT, USDC (method depends on token).

## Flow in Stivium (target)

1. User opens agent → **Activate**
2. Sets spend cap / allowlist / expiry (permissions)
3. Optionally enables **Pay hire with x402** (fee to provider / marketplace)
4. Client receives 402 requirements → signs → B402 `/verify` + `/settle`
5. On success → session marked paid + active

## What ships in the demo

- Checkbox **Pay hire with x402** on the activate panel
- Displayed mock price: **0.10 USDT**, scheme `exact`, network `eip155:97` (testnet)
- On confirm: short mock authorize step → receipt id `x402-mock-…` in the success panel
- **Not** a live B402 settle (no merchant backend in the static Pages site)

## Wiring live B402 later

1. Run a small merchant API (not static Pages alone) that:
   - On hire request, returns HTTP 402 + `paymentRequirements` from B402 `POST /supported`
   - After client pays, calls B402 `verify` then `settle`
2. Point the Stivium activate button at that API
3. Use testnet credentials first; mainnet B402 is access-on-request
4. Keep Altana (or local) session boundaries independent of the payment receipt

Docs: [Binance B402 / x402](https://developers.binance.com/legacy-docs/onchainpay-x402/introduction)

## Honest scope

Mock payment proves the **UX and separation of concerns**. It does not claim production settlement volume or a registered B402 merchant account.
