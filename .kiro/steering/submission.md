# Submission writing standards

Write for a judge who has not seen the repository. State the user problem, the end-to-end path, what is live, what is seeded, and what is mocked. Link directly to the relevant file or public URL.

For Kiroween, recommend one primary category and explain the fit in terms of the actual product. Do not claim Kiro features were used unless the entrant can truthfully describe when and how they were used. Keep credentials private to the Devpost form and never place secrets in public documentation.
